<summary>
- The internal "resume an existing Claude session" step gains the ability to carry a first message into the resumed session.
- When no message is given, the resumed session starts exactly as it does today — byte-for-byte the same command line, no empty argument tacked on.
- A message that is only spaces or tabs counts as no message.
- If the underlying `claude` binary refuses the extra argument, the error is returned to the caller rather than swallowed, so the operator sees a failure instead of silently landing in a bare session.
- Nothing changes for the operator yet: both callers (`task work-on` and `goal work-on`) pass no message in this prompt, so behavior is identical to today.
- The follow-up prompt is the one that actually fixes `task work-on`; `goal work-on` deliberately keeps today's behavior and is fixed by a separate spec.
- Tests pin the exact command line for all three cases (message, no message, whitespace-only message).
</summary>

<objective>
The session-resume mechanism can hand a resumed `claude --resume` session a first turn, while an empty prompt produces argv byte-identical to today's. Both existing call sites pass `""` in this prompt, so the change is behavior-neutral end to end.
</objective>
