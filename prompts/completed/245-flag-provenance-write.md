# Record flag provenance in the same write as the flag

<summary>
- Tasks carry a `flag: true` marker the operator uses to mark work to pick up
- Nothing today records WHO set that flag, so a flag written by an agent is indistinguishable from the operator's own
- This change makes every flag write also record the actor that made it
- The actor is declared by the caller; a write that declares nothing is recorded as `unknown`
- The record lands in the same storage call as the flag, so no read can see a flag without provenance
- The record becomes readable through the existing task detail and list output
- Clearing the flag removes the record with it
- A later write replaces an earlier one, so the field always names the most recent writer
- Tasks that already carry a flag but no record are left untouched and keep working
- Setting the flag to `false` keeps working exactly as it does today
</summary>

<objective>
Make `vault-cli` record who set a task's `flag`, in the same write that sets the flag, and expose that record on the task read surface, so a reader can tell an operator-set flag from an agent-set one — the distinction the approval gate currently rests on convention for.
</objective>
