# Wire task complete and task defer to the own-entry matcher

<summary>
- `vault-cli task complete` now flips the task's own daily-note entry instead of whichever earlier line happened to mention the task.
- A narrative checkbox line that references several tasks — a chain summary or a rollup — is left byte-identical by `complete`.
- `complete` updates every one of the task's own entries on the note, not just the first, so a note carrying a duplicate entry ends fully consistent.
- `vault-cli task defer` now removes only the task's own entries from today's note and no longer deletes a line that merely mentions the task.
- Deferring a task that appears in a chain-summary line no longer destroys that line's prose and its other tasks' completion state.
- When a note holds only a mention and no own entry, both commands leave the note unchanged and still report success, exactly as before.
- Existing daily-note behavior — asterisk versus dash list markers, in-progress to checked transitions, insertion into the Should or Must section — is unchanged.
- Two old test fixtures that encoded the buggy bare-name form are corrected to the documented wikilink entry shape.
</summary>

<objective>
Replace the case-insensitive substring containment in `updateDailyNote` (`pkg/ops/complete.go`) and `removeFromDailyNote` (`pkg/ops/defer.go`) with the shared `ops.IsOwnDailyNoteEntry` matcher, and drop `complete`'s break-on-first-match — so `task complete` flips every one of a task's own daily-note entries and `task defer` removes only its own entries, with narrative lines that merely mention the task left byte-identical instead of being silently skipped over (`complete`) or deleted outright (`defer`).
</objective>
