<summary>
- `vault-cli task work-on <task>` stops handing the operator a session that has already been told to stop.
- The resumed session is now given a first message that re-runs the same work-on command interactively, so it continues into planning and execution instead of idling on the previous turn's "next steps" list.
- The first, headless startup turn is untouched — it still takes safe defaults and still refuses to ask questions it cannot hear the answer to.
- A vault that configures its own work-on command gets that command in the continuation message, not a hardcoded one.
- `goal work-on` is deliberately left alone and still behaves exactly as before.
- No new setting, flag, or toggle — the continuation always happens when the session is resumed interactively.
</summary>

<objective>
Make `task work-on`'s interactive resume hand the resumed session a continuation prompt equal to `<GetWorkOnCommand()> "<task.FilePath>"` — the same bootstrap invocation **without** `--non-interactive` — so turn 2 continues the plan → execute chain instead of idling on turn 1's stop-at-signal instruction. Turn 1 is unchanged.
</objective>
